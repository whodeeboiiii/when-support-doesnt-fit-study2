# 실값 자산 배포 반입 — PH-04 (v1, 2026-08-25)

- 대상: **dossier 실값 24건** + **배정표 1건**. 둘 다 저장소에 커밋하지 않는다(§2.9 · `.gitignore`).
- 근거 명세: §2.3(자산 배치) · §2.4(`DOSSIER_DIR`·`ASSIGNMENT_PATH`) · §2.9(보안) · §5.3(lock) · §5.4(기동 게이트)
- 방식: **볼륨 오버레이**(v1 권고 A 승계). 이미지에는 P00·스키마 더미·문항 자산만 들어가고, 실값은 배포 환경의 볼륨으로만 들어온다.

---

## 1. 왜 볼륨인가

실값 dossier는 **참가자가 실제로 겪은 사건의 재구성**이다. 저장소에 들어가면 그 순간 되돌릴
수 없다 — 커밋 이력은 지워지지 않고, 저장소 접근 권한은 IRB가 승인한 데이터 접근 범위보다
넓다. 그래서 §2.9가 커밋을 금지하고, 코드는 **파일이 없어도 뜨도록**(더미 폴백) 설계돼 있다.

배포에는 두 가지 방식이 가능했다(v1 명세 PH-04): **볼륨 마운트** 또는 **환경변수 주입**.
JSON 24건을 환경변수에 넣으면 크기 제한·이스케이프·회전 절차가 전부 문제가 되므로
**볼륨을 택한다**. 이미 §2.4가 그 전제로 환경변수 두 개를 두고 있다.

---

## 2. 앱이 파일을 찾는 순서 (오버레이)

`backend/app/assets/files.py`의 `dossier_search_paths()`가 정본이다.

```
① $DOSSIER_DIR/Pnn.json              반입한 실값          ← 볼륨
② <이미지>/dossiers/Pnn.json         P00(QA)만 해당        ← 커밋됨
③ schema_dummy/Pnn.json              스키마 더미           ← 볼륨 → 이미지 순
```

배정표는 `backend/app/core/assignment.py`의 `assignment_path()`:

```
① $ASSIGNMENT_PATH                   설정됐으면 반드시 그 파일 (없으면 기동 실패)
② <이미지>/assignments/assignment_v1.json
③ <이미지>/assignments/assignment_dummy.json    → is_dummy=true
```

**이 순서에서 따라 나오는 운용 규칙 셋.**

1. **볼륨에는 실값만 올린다.** 더미는 이미지가 갖고 있다. 24명이 한 명씩 lock되므로(§5.3)
   실값 3건만 올라간 상태도 정상이고, 나머지 21명은 더미로 떠서 기동·시연이 계속된다.
2. **P00은 올리지 않는다.** 이미지에 있고 ②가 잡는다. 볼륨에 복사하면 QA 자산이 두 벌이 되어
   갈라진다.
3. **`ASSIGNMENT_PATH`를 설정했으면 그 파일이 반드시 있어야 한다.** 없으면 기동이 끊긴다 —
   조용히 더미 배정표로 내려가면 **더미를 실은 채 실험이 뜬다**.

## 3. 반입 절차

### 3.1 볼륨 생성·마운트

배포 호스트(Railway 기준, §2.0)에서 서비스에 영구 볼륨 하나를 붙인다.

| 항목 | 값 |
|---|---|
| 마운트 경로 | `/data` |
| dossier 자리 | `/data/dossiers/` |
| 배정표 자리 | `/data/assignments/assignment_v1.json` |

경로 자체는 무엇이든 되지만 **환경변수와 일치**하기만 하면 된다. `/data`를 쓰는 이유는
이미지의 `/app`(소스 트리)과 섞이지 않게 하기 위해서다 — Dockerfile 주석이 경고하듯 `/app`
아래 배치는 `__file__` 기준 경로 계산에 묶여 있다.

### 3.2 환경변수

```
DOSSIER_DIR=/data/dossiers
ASSIGNMENT_PATH=/data/assignments/assignment_v1.json
```

⚠ **배정표 생성 전에는 `ASSIGNMENT_PATH`를 설정하지 않는다.** 설정해 두고 파일이 없으면
기동이 끊긴다(§2절 규칙 3). 파일을 올린 뒤에 변수를 추가하는 순서다.

### 3.3 파일 올리기

로컬에서 lock을 마친 파일(§5.3 — `scripts/lock_dossier.py`)을 볼륨으로 옮긴다. 호스트가
제공하는 방법 중 아래 요건을 만족하는 것이면 무엇이든 된다.

- 전송 구간이 암호화될 것 (호스트 CLI의 SSH/exec 채널 또는 TLS)
- 중간 저장소를 거치지 않을 것 — 메일·메신저·공유 드라이브 경유 금지
- 파일명이 `Pnn.json` 그대로 유지될 것 (`participant_no`와 파일명이 일치해야 로더가 받는다)

Railway CLI를 쓰는 경우의 형태는 아래와 같다. **명령 표기는 CLI 버전에 따라 다르므로
실제 반입 전에 `railway --help`로 확인한다** — 이 문서가 확정하는 것은 위 요건과 결과
상태이지 특정 CLI 문법이 아니다.

```bash
# 서비스 셸에 붙어 디렉터리를 만든다
railway ssh -- mkdir -p /data/dossiers /data/assignments

# 파일 1건씩 (24회 + 배정표 1회)
railway ssh -- sh -c 'cat > /data/dossiers/P05.json' < dossiers/P05.json
railway ssh -- sh -c 'cat > /data/assignments/assignment_v1.json' < assignments/assignment_v1.json
```

### 3.4 검증

재기동 후 **반드시** 아래를 돌린다.

```bash
python scripts/freeze_study_version.py --check
```

출력의 「자산 출처」 블록이 반입 결과를 그대로 말한다.

```
자산 출처 (§2.4 · PH-04)
  dossier 디렉터리 : /data/dossiers (DOSSIER_DIR 오버라이드)
  스키마 더미      : /app/dossiers/schema_dummy (리포 바닥으로 내려감)
  dossier          : 실값 25건 (lock 24건) · 더미 0건
  배정표           : /data/assignments/assignment_v1.json [실값 · assignment_v1 · 24행]
  focal 문항       : focal_items_v1 [실값]
  pairwise 문항    : pairwise_items_v1 [실값]
  동의서 버전      : irb_v1_<승인일>
```

확인할 것 넷.

1. `dossier 디렉터리`에 **(DOSSIER_DIR 오버라이드)** 표시가 있다 — 없으면 변수가 안 걸렸다.
2. `실값 25건` — 배정표 24명 + P00이다. 24건이면 P00이 빠진 것이고, 그건 ②가 안 잡힌 것이다.
3. `lock 24건` · `더미 0건`.
4. 배정표가 `[실값]`이고 `is_dummy`가 아니다.

기동 로그도 같은 사실을 말한다(§5.4) — 더미가 하나라도 있으면 `더미 자산으로 기동` 경고가 남는다.

## 4. 어긋났을 때의 증상

| 증상 | 원인 | 조치 |
|---|---|---|
| 기동 실패 `AssetLocationError: DOSSIER_DIR=…` | 마운트 경로 오타 또는 볼륨 미연결 | 경로 대조. 변수를 비우면 이미지의 `dossiers/`로 돌아간다 |
| 기동 실패 `AssignmentContractError: ASSIGNMENT_PATH=…` | 배정표 파일이 아직 없다 | 파일을 올린 뒤 변수를 설정한다(§3.2 순서) |
| 기동 실패 `배정표 계약 위반` | 24행·제약 위반 (§5.2 · NT-32) | 생성 로그를 확인하고 재생성 — **모집 전에만 가능**(§1.4) |
| 기동 실패 `자산 계약 위반` | dossier 스키마 위반 (§5.3) | 로컬에서 `lock_dossier.py Pnn --check`로 재현 후 수정 |
| 게이트가 PH-03을 보고하는데 파일은 올렸다 | lock 전이거나 `is_dummy` | 「자산 출처」의 `lock N건`을 본다 — 0이면 lock 미실행 |
| 세션 생성 409 | 배정표에는 있는데 dossier가 없다 (§9.1) | 해당 번호 파일 누락. 기동 로그의 `배정표 참가자의 dossier 없음` 참조 |

---

## 5. 교체·롤백

- **dossier 1건 교체**: 해당 참가자의 **세션 시작 전에만** 가능하다(§1.4). 파일을 덮어쓰고
  재기동 → `--check`로 `lock`·hash 확인.
- **배정표 교체**: 생성 후 변경 금지(§1.4). 교체가 불가피하면 같은 seed로 **전체 재생성** 후
  `assignment_v2`로 버전을 올린다. **이미 세션을 마친 참가자가 한 명이라도 있으면 재생성
  불가**이며 시스템은 부분 재배정을 지원하지 않는다.
- **롤백**: 환경변수 두 개를 비우면 이미지의 더미 구성으로 즉시 돌아간다. 볼륨의 파일은
  그대로 남는다.

---

## 6. 파기

연구 종료 후 볼륨의 dossier·배정표는 PH-IRB-4의 보관·파기 일정을 따른다(비식별 전사본과
동일 취급). 볼륨 삭제만으로는 호스트 스냅샷이 남을 수 있으므로, 삭제 전에 파일을 먼저
덮어쓰고 볼륨을 해제한다.

---

## 7. 이 문서가 확정하지 않은 것

- **호스트 CLI 명령의 정확한 문법**(§3.3) — 반입 시점의 CLI 버전으로 확인한다. 문서가
  고정하는 것은 전송 요건과 결과 상태다.
- **볼륨 크기·백업 주기** — dossier 24건은 수백 KB 규모라 최소 용량으로 충분하다. 백업은
  PH-IRB-4의 오프라인 백업으로 갈음할지 호스트 스냅샷을 쓸지 연구팀 결정 사항이다.
