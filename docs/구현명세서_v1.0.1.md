# 0. 이 문서를 10분 안에 이해하기

## 0.1 무엇을 만드는가

Study 1 참가자 중 재초대된 **12명**이, 자신이 실제로 경험한 AI 사회적 지원 **비수용(nonacceptance) 사건의 동일 checkpoint로 재진입**하여, 서로 다른 네 가지 post-nonacceptance re-grounding move(**C1–C4**, substantive uptake × elicitation 2×2)를 **모두 경험**하는 within-participants enactment 실험의 웹 시스템을 만든다. 시스템은 두 개의 화면을 가진다:

1. **참가자 화면** — Zoom 화면공유 상태에서 참가자가 직접 조작하는 실험 인터페이스 (데스크톱 전용)
2. **연구자 콘솔** — 세션 생성·접속 코드 발급, 라이브 모니터, cross-branch review 뷰, dossier 뷰어

> **개발자가 기억할 한 문장**
> 이 시스템은 '판정하는 시스템'이 아니라 '기록하는 시스템'이다. AI1은 **사람이 사전 작성해 lock한 자극**이고, 실시간 LLM 호출은 **AI2 한 턴뿐**이며 그마저 동일한 정책·정보 경계 아래에서 통제된다. 라우팅도, eligible 판정도, 자동 배정도 없다. 시스템의 일은 participant × condition **trajectory(AI1 → User1 → sidecar → AI2 → downstream action → ratings)를 오염 없이 저장**하는 것이다. 참가자 발화는 데이터이므로 항상 자유고, AI 발화는 자극이므로 항상 통제 대상이다(v5.0 §0.1 원칙 승계).

## 0.3 이 시스템이 하지 않는 것

- **무인 운영을 하지 않는다.** 모든 세션은 연구자 동반 원격 세션이다(Zoom·녹화·전사는 시스템 밖 — D-02·D-14).
- 라우팅·eligible 판정·자동 무작위 배정을 하지 않는다 (Stage 0·R1/R2/R3 계열 전면 폐기 — 부록 G).
- AI1을 실시간 생성하지 않는다 — AI1은 참가자별 사전 작성·lock 자극이다.
- 인과 창을 넘는 생성을 하지 않는다 — **AI2 한 턴이 유일한 실시간 생성**이고 AI3는 없다.
- checkpoint의 사실 오류를 시스템에서 수정하지 않는다 — 표시 전용이다(D-08. 구두 언급은 세션 기록으로만 남는다).
- 안전 자동 종료·안전 자원 화면을 시스템에 두지 않는다 — 위기 대응은 연구자 실시간 프로토콜이다(D-10, 부록 D). v5.0 안전 자원 자산(IRB_D16)은 사용하지 않는다.
- sidecar 내용을 hidden ground truth로 취급하지 않으며, **어떤 LLM payload에도 넣지 않는다.**
- Study 1 회고 자료(researcher-only layer)를 AI1·AI2·checker 입력에 소급 주입하지 않는다.
- 관찰 표현(감사·짧은 호응·continuation)을 acceptance의 binary proxy로 코딩하지 않는다.
- 네 조건 중 하나의 보편적 우월을 가정하지 않고, 소표본 2×2에서 population-level factorial effect를 확증하지 않는다.
- 모바일을 지원하지 않는다 — 데스크톱 전용, 모집 안내에 "데스크톱 필수" 명시(D-12).
- 보상 코드를 자동 발급하지 않는다 — 수동 지급, IRB 문안만 명세(D-11).

# 1. 고정된 연구 논리와 구현 원칙

## 1.1 v5.0에서 계승하는 원칙 (계승 선언)

패러다임(무인 대량 웹 실험 → 동반 소표본 enactment)이 바뀌어도 다음 다섯 원칙은 v5.0에서 그대로 계승한다. 각 원칙의 신판 적용은 해당 절에 있다.

1. **정보 방화벽**: 모듈별 입력 allowlist를 표로 동결하고 leakage를 테스트로 막는다 (§1.2, NT-01–NT-04).
2. **자극 통제 / 발화 자유**: AI 발화는 조작물이므로 사전 lock 또는 정책 통제, 참가자 발화는 데이터이므로 항상 자유 (§5, §6).
3. **연구 상태와 구현 상태의 구분** (§1.3): 상태는 뒤로 돌리지 않고, 저장물은 최초 성공 시점에 확정 후 재사용한다.
4. **dead-end 금지**: 모든 오류 경로가 유효한 다음 상태로 수렴한다 (§9.1).
5. **재현성**: 모델·프롬프트·자산의 버전 고정과 전 호출 audit (§2.2.2, §6.8, §8.4).

## 1.2 Evidence boundary — 정보 방화벽 표 (신판)

“AI가 정당하게 이용할 수 있는 evidence”의 경계는 이 연구의 핵심 조작 전제다(논문 초안 §7.3·§7.9). 아래 표를 위반하는 코드 경로는 존재해서는 안 되며, NT-01–NT-04가 이를 상주 검증한다.

- **dossier derivation layer**(자극 4종·residual uncertainty·referent_map·neutral fallback·prohibited inference 목록)는 "시스템 운영 자산"이다: AI1 표시·normalization·fallback에 사용하지만, **derivation layer의 값이 AI2 프롬프트에 직접 삽입되는 경로는 없다** (예외: normalized referent 치환문·fallback 문안 그 자체).
- 구현 규율: researcher_only는 서버에서 **별도 모듈**(`dossier_private.py`)로만 로드하고, LLM payload 조립기(`llm/context.py`)는 해당 모듈을 import할 수 없다(정적 검사 NT-04 — v5.0 T43 방식 승계).

## 1.5 용어 규칙 (명세·코드 주석·논문 공통)

1. **nonacceptance(비수용)**: 참가자가 제공된 지원의 구성요소 또는 대화 진행이 당시 상황·요구·기대에 충분히 맞지 않았다고 판단한 사건의 **event-level analytic term**. 실시간 classifier label이 아니다 — 이 시스템에는 비수용을 "판정"하는 코드가 존재하지 않는다.
2. **AI-visible trouble cue**: 당시 대화에 실제로 표현된, 시스템이 관찰 가능한 trouble 표현. **cue form**(explicit / mitigated / ambiguous / affiliative+detectable trouble)과 **actionability**(0/1/2 — 그 cue와 interactional record만으로 정당화 가능한 bounded adjustment의 정도)는 별개 속성이다. actionability는 **제3의 실험 factor가 아니라** incident-level boundary condition이다 (초안 §6.3).
3. **substantive uptake**: 현재 evidence가 정당화하는 범위에서 **실제 다음 support action이 달라지는 것**(enacted change). "이해했다"·"앞으로 안 그러겠다"는 recognition·policy promise이지 uptake가 아니다. actionability 낮은 사건에서는 non-escalation(제안 보류·범위 축소)도 uptake다 (초안 §7.6).
4. **elicitation**: 사전 lock된 consequential residual uncertainty **1개**에 대한 추가 contribution 요청. "질문이 있는가"가 아니라 "그 질문 전에 가능한 uptake를 수행했는가"가 C2/C4 대비의 축이다.
5. **re-grounding ≠ error recovery**: 복구할 정답 상태를 가정하지 않는다. "grounding sufficiency"는 현재 support purpose에 비추어 다음 move를 정당화할 interactional basis가 형성되었는가를 뜻하며, "AI가 사용자를 많이/깊이 알게 됨"이 아니다.
6. **sidecar**: contemporaneous self-report다. "hidden ground truth", "빠뜨린 정보", "말했어야 했던 내용" 같은 규범적 표현은 문서·코드·문안 전체에서 금지 (초안 §7.8).
7. **enacted downstream action**: naturalistic behavior가 아니라 enacted behavioral choice로만 서술한다.
8. **ID 예약**: `C1–C4`는 실험 조건 전용. 결정 이력은 `D-nn`(부록 E), 테스트는 `NT-nn`(부록 C), 화면은 `P#`/`R#`, 세션 상태는 `SS##`, branch 상태는 `B#`. (v5.0의 확정 결정 C1–C16과의 충돌 회피 — 전환계획 C-2)
9. **표기 통일**: 설계 명칭은 **within-participants design**으로 통일한다(초안의 within-person 혼용은 논문 개정 시 정리 `<TODO: PH-P-2>`).
10. **관찰-회고 분리**: observable response와 retrospectively reported stance를 하나의 acceptance 라벨로 합치지 않는다. continuation ≠ continuation preference (초안 §5.2·§5.4의 금지선을 분석·export 네이밍에도 적용 — `acceptance` 계열 변수명 금지).

- 파생 지표는 전부 분석 시점 계산(런타임 계산 없음). 품질 게이트·배제에 시간 지표를 사용하지 않는다(불변 원칙 승계).

## 3.2 branch 수준 상태 (B, branch_index b ∈ {1,2,3,4})

| 상태 | 이름 | 화면 | 종결/전이 |
|---|---|---|---|
| B0 | REENTRY | P4 | "시작" → B1 |
| B1 | AI1_SHOWN | P5 | 조건 자극 표시(§3.3). 렌더 완료 beacon 기록 |
| B2 | USER1 | P5 | 3분기: `reply`(텍스트 전송) / `no_reply`(답장하지 않음) / `end`(대화 종료) → B3 |

| B4 | AI2_PENDING → AI2_SHOWN | P7 | §6 파이프라인. 성공·fallback 모두 표시 후 → B5 |
| B5 | DOWNSTREAM | P8 | 7선택 1회 → B6 |

| B7 | RESET_DONE | — | b<4면 다음 branch B0, b=4면 SS05 |

- **no_reply/end branch에는 AI2·downstream이 없다.** 이는 실패가 아니라 독립적 trajectory다(초안 §7.9). B6의 문항 적용은 **전 종결 유형 동일 — 12문항 2블록**(D-22 확정, 매트릭스는 §7.3).
- **B2의 조건 자극**: branch_index → 조건은 §3.3 배정표가 결정하며, 표시할 AI1 원문은 dossier derivation layer의 `stimuli[condition]`이다. 최초 표시 시 `branches.condition`·`stimulus_hash`를 저장하고 이후 재사용한다(재추첨·재선택 0건 — NT-07).

## 3.3 배정 — Williams balanced Latin square + 번호 순환 매핑 (D-09)

| Sequence | branch 1 | branch 2 | branch 3 | branch 4 | 배정 참가자 |
|---|---|---|---|---|---|
| S1 | C1 | C2 | C4 | C3 | P01, P05, P09 |
| S2 | C2 | C3 | C1 | C4 | P02, P06, P10 |
| S3 | C3 | C4 | C2 | C1 | P03, P07, P11 |
| S4 | C4 | C1 | C3 | C2 | P04, P08, P12 |

- 매핑은 결정론: `sequence_index = (participant_no − 1) mod 4 + 1`. 코드·자산 어디에도 별도 배정 로직을 두지 않는다.
- 네 조건이 각 serial position에 1회씩, 12개 directed first-order adjacent pair가 전 sequence에 걸쳐 각 1회씩 나타난다(논문 초안 §7.7). NT-06이 표 자체를 검증한다.
- counterbalancing은 carryover **제거**가 아니라 **균형화** 장치로만 해석한다 — first-opportunity/carryover 태깅은 §7.6.

## 3.4 branch reset 의미론 (동결)

- **서버**: AI2 payload는 branch마다 {dossier ai_visible + 해당 branch User1(정규화)}로 **매번 새로 조립**한다. 세션 누적 대화 이력이라는 개념 자체가 없다. 타 branch의 User1·AI2·sidecar가 payload에 포함되면 즉시 결함이다(NT-10).
- **UI**: B7에서 채팅 화면을 checkpoint 상태로 되돌리고 이전 branch의 입력·응답을 표시하지 않는다.
- **한계의 명시**: 기술적 reset이 참가자의 기억·해석을 제거하지 못한다는 해석 규칙(초안 §7.7)은 분석 층(§7.6)의 태깅으로 다루며, 시스템은 균형화(§3.3)와 격리(NT-10)만 보장한다.

## 3.5 새로고침·뒤로가기·중복 제출·재접속

- 새로고침: 서버 저장 상태(SS·B·표시된 자극·AI2 산출물·문항 순서)를 복원한다. 자극·순서 재추첨 없음 (NT-08).
- 뒤로가기: 연구 상태 후퇴 없음. 이전 화면은 읽기 전용으로도 재표시하지 않는다(단순화 — 리뷰는 P10에서만).
- 중복 제출: 제출 단위 idempotency key(`session_id, branch_index, step`) — 재제출은 200 + 기존 레코드 반환 (NT-09).
- 재접속: 동일 번호+코드 재입력 → 저장 지점 복원. 코드 TTL 24h 내 재사용은 동일 세션 복구로만 동작한다(새 세션 생성 아님).

# 5. 표본·incident dossier·AI1 자극 파이프라인

## 5.1 표본과 참가자 번호

- **N=12** (D-15). Study 1 참가자 중 재초대 — main 포함 기준(논문 초안 §6.3·§7.2): 해당 checkpoint에 **observable trouble cue가 존재**하고 incident detail이 충분한 사건. pure latent case(회고로만 확인된 비수용) 제외.

# 6. AI2 생성 정책

## 6.1 파이프라인 개요 (동기 — 참가자 로딩 화면 내 완료)

```
User1 확정(reply)
  → [1] referential normalization (규칙 기반, §6.4)
  → [2] payload 조립 (allowlist §6.2)
  → [3] AI2 생성 (MAIN 모델, 정책 프롬프트 부록 A.1)
  → [4] 규칙 검사 (§6.5 R-계열)
  → [5] LLM integrity checker (VALIDATOR 모델, 부록 A.2)
  → 위반 시: 위반 피드백 포함 재생성 1회 → 재위반 시 dossier neutral_fallback
  → 표시 + llm_calls audit 기록
```

- 시간 예산: [3] 90s + [5] 45s + 재생성 여유. 최악 경로에서도 §9.1 타임아웃 규칙이 fallback으로 수렴한다(dead-end 금지).
- no_reply/end branch는 파이프라인 자체를 호출하지 않는다.

## 6.2 입력 계약 (allowlist — 동결)

AI2 payload는 정확히 다음으로 구성한다: ① 시스템 프롬프트(정책, 부록 A.1 — 전 조건·전 참가자 동일) ② dossier `ai_visible` layer(checkpoint 정보) ③ 해당 branch의 User1(정규화본; 원문은 audit 저장). **AI1 원문·조건 라벨·sequence·sidecar·researcher_only·타 branch·평정·사전설문은 어떤 형태로도 포함하지 않는다**(§1.2, NT-01·NT-10).

## 6.3 정책 원칙 (초안 §7.9 — 전 조건 동일 적용)

1. User1에서 명시적으로 제공된 correction·request·boundary는 반영한다.
2. 표현되지 않은 새로운 감정·support type·선호·정체성·세계관·conversation-continuation intention을 추론하지 않는다.
3. 현재 interactional evidence만으로 정당하게 처리 가능한 mismatch는 그 범위에서 반영한다.
4. 다음 support move를 실질적으로 바꿀 consequential residual uncertainty가 남아 있을 때에만 **clarification question 최대 1개**를 허용한다.
5. 기존 interaction 범위를 벗어난 새로운 주제·장기 계획으로 임의 확장하지 않는다.

## 6.4 referential normalization (규칙 기반 자동 — D-04/O-3)

- 목적: AI1 전문을 payload에서 제외하면서도 "응, 그렇게 해줘" 류 지시 참조를 해석 가능하게 한다(초안 §7.9).
- 구현: ① dossier `referent_map`에 AI1별 제안 proposition을 **사전 등록**(자극 작성 시 함께 작성 — C2/C4의 질문, C3/C4의 조정 제안 등 지시 대상이 될 수 있는 명제) ② config의 지시표현 패턴 목록(초기 목록 부록 A.3, `normalization_patterns_v1.json`)과 User1을 대조 ③ 유일 매칭 시 해당 proposition으로 **최소 치환**, 다의·무매칭 시 **치환하지 않고 ambiguity 유지**(임의 보완 금지).
- 새로운 의미·참가자 선호를 추가하지 않는다. 치환은 명시 지시 표현의 지시 대상 복원에 한정한다.
- 저장: `user1_raw`, `user1_normalized`, `normalization_applied`(bool), `matched_pattern_id`, `referent_id`. 전 조건 동일 규칙(NT-11), fixture 검증(§10.1).

## 6.5 integrity check (규칙 + LLM checker — O-4)

**규칙 계층 (결정론, 서버):**

| ID | 검사 | 판정 |
|---|---|---|
| R-1 | researcher_only·sidecar 유래 문자열의 출력 내 등장 (필드 값 문자열 대조) | 위반 |
| R-2 | 타 branch User1/AI2 문자열의 등장 | 위반 |
| R-3 | 질문 수 > 1 (의문부호·의문형 종결 휴리스틱 — [파일럿 확정: 검출 규칙 1회 조정 가능]) | 위반 |
| R-4 | 출력 길이 상한 초과 (기본 1,200자 [파일럿 확정]) | 위반 |

**LLM checker (VALIDATOR 모델, JSON 판정 — 부록 A.2):** 초안 §7.9의 5항 중 규칙으로 못 잡는 것 — ① unsupported inference(미표현 감정·선호·continuation 추론; dossier `prohibited_inference` 목록을 판정 참조로 제공) ② 새 주제·장기 계획 expansion ③ User1의 명시적 correction·boundary 미반영. 입력: ai_visible 요약 + user1_normalized + AI2 초안 (+ prohibited_inference). 출력: `{violations: [{type, span, rationale}], pass: bool}`.

- 종합 판정: 규칙 위반 **또는** checker 위반 → 재생성 1회(위반 유형 피드백 포함, 동일 모델·정책) → 재위반 → `neutral_fallback`.
- checker 자체 실패(타임아웃·파싱 실패)는 §9.1: 규칙 계층만으로 판정하고 `checker_skipped` audit flag.
- 기록: 최초 생성·위반 유형·재생성·fallback 여부 전부 `llm_calls`·`generations`에 저장, 분석 시 generation integrity로 보고(초안 §7.9).

## 6.6 neutral fallback (O-4b)

- 참가자별 1종, dossier `derivation.neutral_fallback`에 사전 작성·lock. 요건: 사건 맥락과 자연스럽게 연결되되 신규 추론·신규 질문 없음(사실상 C1 계열의 중립 승인+비확장 문안). 사용 시 `fallback_used=true` — 해당 branch는 분석에서 generation integrity와 함께 보고.
- fallback 문안 자체도 규칙 계층(R-3·R-4)을 자산 계약 테스트에서 통과해야 한다(NT-21).

## 6.7 생성 파라미터·재현성

- `prompt_config_v1.json` 단일 정본: 시스템 프롬프트·checker 프롬프트·패턴 목록 버전·파라미터(temperature, max_tokens)·`prompt_hash`. v5.0 §6.10 규율 승계.
- 모델 고정: `MAIN_MODEL_ID`/`VALIDATOR_MODEL_ID` + provider 고정 3중 정책(§2.2.2). 매 호출 `provider_reported_model` 저장, 변경 감지 시 notify.
- `DEV_MODE=true`에서는 fake LLM(구 리포 `tests/fake_llm.py` 이식)이 결정론 응답을 반환한다 — 팀 시연·CI 공용.

## 7.6 사후 코딩·태깅 (시스템 밖 — export가 지원)

## 8.3 User1 제출 → AI2 표시 시퀀스 (reply branch)
