# 0. 이 문서를 10분 안에 이해하기

## 0.1 무엇을 만드는가

Study 1 참가자 중 재초대된 **24명**이 각자 자신이 실제로 경험한 AI 지원 **비수용(nonacceptance) 사건의 AI-visible trouble checkpoint로 재진입**하여, R/U/Q building block의 조합으로 만든 네 조건(C1=R, C2=R+Q, C3=R+U, C4=R+U+Q) 중 **하나의 focal condition만 완전한 상호작용으로 경험**하고(AI1 → User1 → sidecar → AI2 → User2/종료), focal 측정이 끝난 뒤에만 **나머지 세 AI1을 비상호작용 대안으로 순차 노출**받아 **세 개의 targeted pairwise contrast**(Sequence C2 vs C4 / Scope C1 vs C3 / Stopping C3 vs C4)를 평정하고 contrastive interview에 응하는 실험의 웹 시스템을 만든다. 화면은 둘이다:

1. **참가자 화면** — Zoom 화면공유 상태에서 참가자가 직접 조작하는 실험 인터페이스(데스크톱 전용)
2. **연구자 콘솔** — 세션 생성·접속 코드 발급, 라이브 모니터, contrastive interview 지원 뷰, dossier·배정표 뷰어

> **개발자가 기억할 한 문장**
> 이 시스템은 '판정하는 시스템'이 아니라 '기록하는 시스템'이다. AI1은 **사람이 사전 작성해 lock한 R/U/Q segment를 시스템이 조립한 자극**이고, 실시간 LLM 호출은 **AI2 한 턴뿐**이며 그마저 동일 정책·정보 경계 아래 통제된다. 배정은 **사전 생성된 배정표를 읽기만** 하고, 라우팅도 eligible 판정도 없다. 시스템의 일은 한 참가자의 **focal trajectory(AI1 → User1 → sidecar → AI2 → User2/종료 → focal 평정) → 대안 노출 순서 → pairwise 판단**을 오염 없이 순서대로 저장하는 것이다. 참가자 발화는 데이터이므로 항상 자유고, AI 발화는 자극이므로 항상 통제 대상이다.

## 0.3 이 시스템이 하지 않는 것

- **무인 운영을 하지 않는다.** 모든 세션은 연구자 동반 원격 세션이다(D-02 승계).
- 배정을 계산하지 않는다 — **배정표(`assignments/assignment_v1.json`)를 읽는다.** 배정표 생성은 오프라인 스크립트(§5.2)이며 런타임 무작위화는 **P8 평정 블록 내 문항 순서뿐이다**(pairwise 문항 순서는 D-42로 고정).
- AI1을 실시간 생성하지 않는다 — AI1은 참가자별 locked R/U/Q segment의 **결정론적 조립**이다(§5.4).
- **AI3를 생성하지 않는다**(Q&A #5, D-33). User2는 기록만 하고 AI 응답을 만들지 않는다.
- **User1을 선택 사항으로 두지 않는다**(Q&A #2, D-32) — no_reply/end 분기는 없다. 이탈은 AI2 이후의 downstream(P7)에서만 측정한다. User1 직전 enacted-choice 문항도 두지 않는다(D-27).
- ~~사전 설문이 없다(Q&A #1, D-31)~~ → **2026-08-27 복원**(D-44). 동의 직후·checkpoint 직전에 12문항을 받는다(§4.1S·§7.0). 다만 **하지 않는 것은 그대로다**: 사전설문 응답을 조건 효과의 조절변수로 쓰지 않는다(participant characterization 전용 — RQ3의 confirmatory moderator 아님). 개인차 척도 4종(§7.0 배제 목록)도 넣지 않는다.
- **referential normalization이 없다**(D-34) — AI2 입력에 focal AI1 원문이 들어가므로 지시 복원이 필요 없다.
- 대안 AI1에 대한 User1·sidecar·AI2·개별 평정을 받지 않는다(초안 §7.10 — 대안은 contrastive referent).
- 네 AI1의 종합 선호 순위·overall preference index를 산출하지 않는다(초안 §7.11).
- sidecar 내용·researcher_only 층·대안 AI1 3종·평정·pairwise·checkpoint 수정 diff의 **어떤 값도 LLM payload에 넣지 않는다.**
- 안전 자동 종료·안전 자원 화면·분류기가 없다(D-10 승계). 모바일 미지원(D-12). 보상 자동 발급 없음(D-11).
- **LLM을 evidence coding·R/U/Q 도출의 judge로 쓰는 도구를 이 시스템 안에 두지 않는다**(Q&A #4, D-36) — 인간 코딩 이후 sensitivity/audit용 third reading은 시스템 밖 별도 도구다.

v1.0.1의 다섯 원칙은 그대로 계승한다: ① 정보 방화벽(모듈별 allowlist 표 + leakage 테스트) ② 자극 통제 / 발화 자유 ③ 연구 상태와 구현 상태의 구분(최초 성공 시점 저장 후 재사용) ④ dead-end 금지 ⑤ 재현성(모델·프롬프트·자산 버전 고정 + 전 호출 audit). 바뀐 것은 **세션의 골격**(4-branch within → focal 1회 + 대안 노출 + pairwise)과 **방화벽 표의 행**이다.

## 1.5 용어 규칙 (명세·코드 주석·논문 공통)

1. **nonacceptance** — event-level analytic term. 판정 코드 없음(승계).
2. **AI-visible trouble checkpoint** — 실제 대화에서 AI가 관찰할 수 있었던 trouble turn 직후 시점. v1.0.1의 cue form 분류(explicit/mitigated/…)는 **폐기**(초안 신 §6에서 삭제). `trouble_cue`는 텍스트 하나다.
3. **R / U / Q** — recognition segment / minimum substantive uptake segment / minimum elicitation segment(초안 §6.3·§7.5). 코드·자산 키는 `r`, `u`, `q`. "uptake"·"elicitation"이라는 construct 명칭은 참가자 화면에 쓰지 않는다.
4. **evidence-bounded actionability / A-level** — `A0 | A1 | A2`는 **incident descriptor**이지 experimental factor·participant type이 아니다(초안 §6.4·§7.5). 배정표 제약(편중 방지)과 export 열에만 쓴다. 코드에서 `actionability`를 조건·분기·검증의 입력으로 쓰면 결함이다.
5. **focal / alternative** — focal은 완전 상호작용을 경험하는 1조건, alternative는 AI1까지만 노출되는 나머지 3조건. "branch"라는 말은 v2.0에서 쓰지 않는다(4-branch 설계의 잔재).
6. **contrast** — `sequence`(C2 vs C4), `scope`(C1 vs C3), `stopping`(C3 vs C4). 이 세 쌍만 존재한다. 코드에 다른 pair를 만들지 않는다.
7. **sidecar** — temporal provenance check(초안 §7.8). "withholding detector"·"hidden ground truth"·"말했어야 했던"은 금지 표현. `provenance ∈ {preexisting, prompt_evoked, uncertain}`는 참가자 자기보고이고, **deliberate withholding은 사후 코딩**이다(시스템 값 아님).
8. **User2 / 종료(downstream)** — AI2 이후의 enacted choice. "이탈 유형"은 enacted behavioral choice이지 naturalistic behavior가 아니다.
9. **설계 명칭** — 원고·명세 공통으로 "focal between-participants enactment + within-participant contrastive evaluation(stated boundary judgment)". "between"만 쓰지 않는다.
10. **관찰-회고 분리**(승계) — `acceptance` 계열 변수명 금지.

## 2.10 클라이언트 규칙 (승계 + D-38 개정)

데스크톱 전용, 뷰포트 **폭 < 768px 또는 높이 < 600px** 차단(D-38 — 종전 폭 < 1024px). 채팅 UI 우측 참가자·좌측 AI, AI1 표시 전 타이핑 인디케이터.

참가자 UI 디자인 시스템 [제안, D-39] — 배경 흰색 위에 세 층만 얹는다.

- **파랑(accent)** = 시스템이 요구하는 것. 1차 버튼은 **채움**, 선택 상태(카드·Likert)는 **파랑 테두리 + 연파랑 배경**, 재구성된 사건 카드는 연파랑 배경. 채움/윤곽으로 "눌러야 할 것"과 "내가 고른 것"을 가른다.
- **노랑(guide)** = 연구자가 참가자에게 건네는 말. **화면 상단 지시문 블록 전용**이며 버튼에는 쓰지 않는다(노랑 위 흰 글자는 대비 미달).
- **무채색** = 자극. **AI 말풍선에는 색조를 넣지 않는다** — 제약은 색상(hue)이지 명도가 아니다. 채움은 R=G=B인 회색(`#F2F2F2`)이고, 흰 카드 위에서 말풍선이 묻히지 않게 흰색을 쓰지 않는다. 색조가 들어가면 따뜻함 지각을 건드려 recognition·uptake 평정(초안 §7.11)과 교락한다.

**새 응답 하이라이트**: focal AI1 · 대안 AI1 3종 · AI2는 말풍선 **바깥에** 아주 옅은 파랑 링이 한 번 번졌다가 남는 표시를 **완전히 동일한 스타일·타이밍**으로 받는다. 정의는 `.bubble-new` 한 곳뿐이고 화면은 boolean만 넘긴다 — 조건마다 표시가 갈리면 그 자체가 조작이다. 화면당 하이라이트는 지금 판단 대상인 AI 응답 하나뿐이다(P4=focal AI1, P6·P7=AI2, P9=해당 대안).

**진행 표시(스텝 인디케이터)는 두지 않는다** — 남은 분량 수치가 조건 수·대안 수의 실마리가 된다(§4.10). §4.9의 "다른 응답 1/2/3" 라벨과 §4.10의 pair 위치는 화면 라벨이지 진행 표시가 아니다.

**모션**: 화면 전환·말풍선 등장은 200–220ms CSS 애니메이션이다. **beacon 타이밍을 바꾸지 않는다** — 마운트도 effect도 미루지 않으므로 `screen_enter`·`render_complete`는 그대로 발화한다. `prefers-reduced-motion: reduce`에서는 모션을 끄되 하이라이트 **표시 자체**는 정적으로 남긴다. 다크모드는 도입하지 않는다(§0.4).

본문은 16px 밑으로 내리지 않는다 — Zoom 화면공유는 한 번 더 축소되어 상대에게 도달한다.

임계값 근거: 768은 `.screen`의 max-width(760px)가 포화되는 최소 폭이라 그 위로는 단일 컬럼 화면의 본문 폭이 참가자 간에 동일하다. 높이 600은 폭만으로는 통과하는 가로 모드 휴대폰(높이 390–440px)을 걸러낸다(D-12). 종전 1024px은 ① 자신이 내세운 표시 균일성 근거와 맞지 않았고(2단 비교 화면의 max-width는 1100px이라 1024–1100 구간에서 열 폭이 달라진다) ② Zoom 화면공유 중 좌우 분할(1920 모니터 → 960px) 같은 정상적인 데스크톱 사용을 막았다. 표시 조건의 균일성은 차단이 아니라 §4.0의 viewport 기록으로 사후 확인한다.

## 2.11 시간 측정·이벤트 (승계, 축소)

## 3.3 대안 노출·pairwise 진행 인덱스

- `sessions.alt_index ∈ {1,2,3}`: P9에서 표시할 대안의 위치. 최초 진입 시 `alt_exposures` 행(position, condition, stimulus_hash, rendered_at) 생성 후 불변. "다음" → `advanced_at` 기록 + index 증가. 3 완료 → SS07.
- `sessions.pair_index ∈ {1,2,3}`: P10에서 표시할 contrast의 위치. 좌우·contrast는 배정표에서 읽어 최초 표시 시 `pairwise_views` 행에 저장 후 불변. 제출 → index 증가. 3 완료 → SS08.
- 대안 노출 순서는 **focal condition을 제외한 세 조건의 순열**이다. 배정표 행의 `alt_order`가 focal을 포함하면 로더가 기동을 끊는다(NT-32).

## 3.4 checkpoint 수정본 의미론 (D-25)

- P2에서 참가자가 segment를 수정하면 `checkpoint_edits`에 `(segment, original🔒, edited🔒, edited_at)`을 **누적**한다(한 segment 여러 번 수정 가능, 최종본 = 마지막 행). 확인 제출 시 수정 종료 — 이후 화면·AI2 입력은 전부 **최종 수정본(effective checkpoint)** 을 쓴다.
- AI1은 **수정과 무관하게 locked 자극 그대로** 표시된다. 수정이 AI1의 전제(문제된 component·trouble cue)를 바꾸면 자극 정합성이 깨질 수 있다 — 시스템은 막지 않고 **`trouble_cue`·`problematic_ai_response` segment 수정 시 R2 경보 + notify**를 보내 연구자가 구두 확인·계속/abort를 판단한다(부록 D.3). 판단은 flag로 기록.
- dossier hash·stimulus_hash는 바뀌지 않는다. `focal_runs.checkpoint_edited(bool)`·`edited_segments(jsonb)`를 export에 노출한다.
- 수정 입력창은 **사실관계 정정용**이며 안내문([정본] §4.2)이 "속마음을 다시 설명하지 않으셔도 됩니다"를 포함한다. 수정본에 private preference가 들어오는 것은 시스템이 판정하지 않는다(판정 코드 금지) — 연구자 메모(flag)와 사후 코딩의 몫이다.

## 3.5 새로고침·뒤로가기·중복 제출·재접속 (승계)

서버 저장 상태 복원, 재추첨·재생성 0건(NT-08), idempotency key = `(session_id, step[, index])`(NT-09), 뒤로가기 후퇴 없음, 재접속 = 동일 번호+코드.

**참가자에게 후퇴는 없다. 되돌리기는 연구자 개입이다** `[파일럿 확정 2026-08-26]`. 참가자 화면의 뒤로가기·새로고침은 여전히 전이가 아니라 복원이고, 참가자 실수의 복구 경로는 연구자의 **rewind**(§9.1)다 — abort·dropout과 같은 계열이며 콘솔에서만 실행되고 `audit_logs`에 남는다. idempotency가 상태 자체이므로(구현: `core/idempotency.py`) 되돌린 뒤의 재제출은 재제출이 아니라 신규 제출로 처리된다.

## 5.4 AI1 자극 — segment 조립 (D-35)

| 조건 | 조립 | 질문 수 |
|---|---|---|
| C1 | `r` | 0 |
| C2 | `r + " " + q` | 1 |
| C3 | `r + " " + u` | 0 |
| C4 | `r + " " + u + " " + q` | 1 |

- `Dossier.stimulus(condition)`이 조립한다(런타임마다 동일 — 결정론). `stimulus_hash`는 조립 결과의 sha256.
- **조립은 둘이다** (D-40): `assemble(condition)`은 위 표 그대로이고 hash·`stimuli_meta`·자산 계약의 기준이다. `presented(condition)`은 거기에 무대지시를 얹은 **표시·전달본**으로, C3 = `r u NOTE` · C4 = `r u NOTE q`이고 C1·C2는 `assemble()`과 같다(§4.4). 무대지시는 자산 파일에 없다 — 조건이 아니라 **u의 존재**가 붙는 자리를 정하는 상수다.
- **기동 게이트 계약**(NT-20·22·23 개정): `r`·`u`·`q` 비어 있지 않음 / `r`·`u` 질문 0개, `q` 질문 정확히 1개 / `stimuli_meta`가 조립 결과 계량과 일치 / `neutral_fallback` 질문 0·1,200자 이하 / 세 segment 어디에도 researcher_only 문자열 미포함(8자 이상 부분 일치 — 승계 임계) / `provenance` 키가 ai_visible 텍스트 필드 전부를 덮음.
- 길이: filler로 맞추지 않는다. 기록만(초안 §7.5).
- 자극 작성·QC 규율(초안 §7.5): least-assumptive U, minimum branching Q, 독립 second researcher QC(`stimulus.qc`). **LLM은 locked content의 wording assistant로만**; derivation judge 금지(D-36). 시스템은 이 절차를 강제하지 않고 QC 필드의 존재만 검증한다.

## 6.1 파이프라인 (승계 — normalization 단계 제거)

```
User1 확정 → sidecar 제출 → [1] payload 조립(§6.2) → [2] AI2 생성(MAIN) → [3] 규칙 검사 R-1·R-3·R-4
```

## 6.2 입력 계약 (allowlist — 동결, D-34)

AI2 payload = ① 시스템 프롬프트(부록 A.1 v2 — 전 조건·전 참가자 동일) ② **effective checkpoint**(참가자 수정 반영 ai_visible) ③ **focal AI1 표시본**(= 참가자가 본 그대로. C3·C4는 무대지시 포함 — D-40) ④ **User1 원문**. **조건 라벨·R/U/Q 구분·대안 AI1·sidecar·researcher_only·evidence_code(prohibited_inference 제외)·배정표·평정·User2는 어떤 형태로도 포함하지 않는다.** `context.build_ai2_payload(effective: EffectiveAiVisible, focal_ai1: str, user1: str, *, violation_types)` — 시그니처가 allowlist다(NT-01 개정).

## 6.3 정책 원칙 (초안 §7.9 — 변경 없음)

① User1의 명시적 correction·request·boundary 반영 ② 미표현 감정·지원 유형·선호·정체성·continuation 추론 금지 ③ 현재 evidence로 처리 가능한 mismatch는 그 범위에서 반영 ④ consequential residual uncertainty가 남을 때만 clarification **최대 1개** ⑤ 새 주제·장기 계획·위기 상담으로 확장 금지. 정당화(리뷰 (l)): common policy는 bounded-uptake + conditional-elicitation 규범을 **모든 focal condition에 동일한 digestive tract으로** 제공하기 위한 선택이며 AI2 이후 결과는 trajectory의 property로 해석한다.

## 6.4 integrity check (승계 개정)

| ID | 검사 | 판정 |
|---|---|---|
| R-1 | researcher_only·sidecar·checkpoint 수정 전 **원문**(수정된 segment의 original)·평정·User2 유래 문자열의 출력 내 등장(8자 이상, payload에 정당히 포함된 문자열 제외) | 위반 |

# 7. 측정

## 7.0 사전 설문 (P1S — §4.1S, 자산 placeholder, D-44)

**participant characterization 전용이며 RQ3의 confirmatory moderator로 사용하지 않는다**(**구 초안** §7.4 — §4.1S의 출처 경고 참조). 쓰임은 둘이다: ① 표본 기술 ② participant-level trajectory·negative case 해석용 맥락.

- **합산하지 않는다.** 자산에도 테이블에도 소계·총점 열이 없다(§8.1). DDI 발췌 4문항은 **validated short form이 아니며** 총점을 원 척도(Kahn & Hessling 2001)와 동등하게 해석하지 않는다.
- **역채점을 저장 시점에 적용하지 않는다.** 자산의 `reverse` 플래그는 분석 시점의 정보이고, export는 원자료 + 플래그를 그대로 내보낸다(부록 B) — export가 미리 뒤집으면 원자료가 사라진다.
- **배제(구 초안 §7.4의 결정 — 재도입하려면 논문 개정 동반)**: Mind Perception · psychological reactance · perceived stress · Brief COPE는 넣지 않는다.
- ② 「빗나갔을 때의 평소 대응」 5지는 §7.4 downstream 6코드와 **다른 축이다** — 여기는 평소 습관, 거기는 이번 focal에서의 행동이다. 코드 이름을 맞추지 않는다.
- ⚠ **용어 충돌**: 신 초안 §7.11의 User Re-grounding Work 코드에 `new support-relevant disclosure`가 있다. 그쪽은 **턴 수준 행동**이고 여기 `disclosure_1·2`는 **성향 자기보고**다. 논문·분석에서 같은 단어를 쓰면 읽는 사람이 구분하지 못한다 — 변수명·보고 문면에서 갈라 쓴다(PH-P-7과 함께 처리).

## A.2 integrity checker v3 (VALIDATOR) `[PI 승인 2026-08-27 · lock]`

정본 문안은 `prompts/prompt_config_v2.json`의 `integrity_checker.system`이다. v2 → v3 변경 여섯:

1. **판정 대상을 초안으로 한정**하고, [AI의 직전 답변]의 표현을 초안의 위반으로 **귀속 금지**. — v2에서 checker가 **AI1의 `u` segment 원문**을 AI2의 위반으로 잡았다(P23). D-40으로 AI1에 무대지시가 붙은 뒤 AI2가 uptake를 이어받을 유인이 커져 이 조항의 무게가 커졌다.

3. **비위반 사유 4종** 명시: 사용자 메시지 반영 / 제안의 설계 근거 서술 / 조건부·선택지·단정 유보 / 사용자 표현을 같은 강도로 되짚기.

5. 금지 목록을 **참고 목록**으로 격하 — 목록이 언급하는 주제가 초안에 등장했다는 사실만으로는 위반이 아니다.
6. `expansion`에 "사용자 메시지가 허용한 범위 안의 구체 제시는 확장이 아님" 추가 + **보수 판정**("애매하면 위반 아님").

**v3.1** `[PI 승인 2026-08-27]` — 실모델 재검에서 남은 오탐 두 갈래를 막는다. 규칙 추가가 아니라 **이미 있는 규칙이 적용되게** 하는 보강이다: ⑦ (c)에 "그 감정·사정이 [대화 맥락]에 이미 있으면 (c) 불성립 = 위반 아님"을 명시(표현이 달라도 같은 내용이면 같게 본다) ⑧ "목록의 항목이 맥락·사용자 메시지에 이미 있는 내용을 가리키면 그 항목은 적용하지 않는다 — 목록은 대화 전에 적은 것이라 대화에 나온 내용을 이기지 못한다" ⑨ 대조 예시 2건 추가(맥락에 있는 표현 되짚기 / 제3자를 배려한 설계 근거).
